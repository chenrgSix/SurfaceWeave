# 说一句，界面就变

这个实验室把“随时改变 UI”直接放到眼前：左边是对话，右边是一整个可操作的应用。可以用固定模板，也可以临时接入自己的模型，让它生成真实 SurfaceWeave 语义操作。

![对话式应用实验室](/conversation-playground.png)

## 开始体验

在仓库根目录运行 `pnpm install --frozen-lockfile`，然后 `pnpm dev`。使用 Node 22。默认地址是 `http://127.0.0.1:5175`，无需 API Key 或后台。

先在右边填写一句交接备注，然后按这个顺序发送：

1. **午夜紫**：整个页面换色，包含菜单、指标、图表和表单。
2. **菜单到顶部**：左侧导航移到上方，内容区重新铺开。
3. **表单变决策卡**：选择框变成业务对比卡，审批前置，数据保留。
4. **打开双视图**：两个独立的 Renderer 同时编辑同一份 Surface 数据。
5. **变成简报**：暖色主题、顶部导航、单栏内容、完整概览一起改变。
6. **撤销上一条**：恢复刚才的界面结构，保留最新输入。

![主题和结构一起变化](/conversation-playground-midnight.png)

## 十条对话模板

| 模板            | 实际操作                                              |
| --------------- | ----------------------------------------------------- |
| 午夜紫 / 薄荷绿 | 对页面根节点 `setProps`，选择可信主题枚举             |
| 菜单到顶部      | `moveNode` 把导航移入正文容器，更新导航布局枚举       |
| 表单变决策卡    | `replaceComponent`、`groupNodes`、`moveNode` 原子批次 |
| 进入专注模式    | 隐藏概览、指标和额外视图，保留编辑工作台              |
| 打开双视图      | 显示第二视图并应用双栏 LayoutSpec；窄屏降级为单栏     |
| 工作台置顶      | 把实际工作台节点移到内容区第一位                      |
| 变成简报        | 主题、导航、可见性和节点顺序在同一批次变更            |
| 紧凑布局        | 减少间距、切换密度令牌并显示运行时事件                |
| 恢复页面布局    | 恢复初始页面树，业务表单和数据不重置                  |

未配置模型时，可以直接点击模板，也可以在输入框提交模板原句或短名称；未知文字不会被猜测执行。配置模型后，自由输入走 API，模板按钮仍固定映射、不调用模型。

## 临时接入模型

点击右上角 **接入模型**，填写 API Base URL、模型 ID、临时 API Key，阅读并确认发送范围，然后启用。保存配置不会请求 API；界面标记“已配置”，不代表已经验证连通。

![临时模型配置与发送范围](/conversation-model-settings.png)

- 协议是 OpenAI 兼容的 **Chat Completions + function calling**。Base URL 支持 `https://你的服务商/v1` 或完整 `/chat/completions` 地址；不是 Responses API。模型 ID 由使用者填写。
- Key 通过 `Authorization: Bearer …` 发送到界面显示的精确地址。远程仅允许 HTTPS，本机 `localhost`、`127.0.0.1`、`[::1]` 可以使用 HTTP；无鉴权的本机接口可以不填 Key。
- 这是浏览器直连，服务商须允许该页面来源的 CORS 以及 `Authorization` / `Content-Type` 请求头。不做隐藏代理、不携带 Cookie、不跟随重定向，也不自动重试。
- 配置只保存在当前页面内存，不写 localStorage、sessionStorage、Cookie 或仓库。**新会话、刷新、断开会清除临时配置**；这不是安全擦除浏览器内存的承诺。
- 每次发送包含当前页面树、文字标签、组件描述、你的指令及最近 10 条对话；不发送业务表单 `data`。不要在对话或页面标题里填写秘密。
- 浏览器内存的 Key 仍可被扩展、开发者工具或恶意脚本读取。仅使用可撤销、低额度测试 Key；生产使用服务端代理。[OpenAI 官方密钥说明](https://developers.openai.com/api/reference/overview#authentication)同样要求避免在客户端暴露密钥。

试着自由描述一个模板里没有的组合：

> 把标题改成“晚班恢复指挥台”，切成午夜紫，菜单放顶部，隐藏概览，打开两个同步工作台，间距设成 27。然后把运输方案换成对比卡。

模型收到真实的 Surface 树、版本和注册组件 schema，通过 [`tools` / `tool_calls`](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 返回通用操作，不是选择模板 ID。模型推理质量和提供商兼容性由使用者的配置决定。

### 如何核查是真正执行

对话中 **模型回复 · 非执行凭证** 仅为模型文字。**SurfaceWeave 运行时** 的回执才表示真实结果，可展开查看模型原始参数、实际版本及变更前后的 Surface 树。模型只说“完成”但没有调用工具时，运行时明确显示“没有执行任何界面操作”。错误不会偷偷改用预设模板。

每次对话最多 4 轮请求，每轮最多一个工具调用、24 个操作。一个批次只修改一份 Surface，在 SDK 中原子提交；**多个批次不构成跨 Surface 事务**。后续失败或停止时，之前的成功批次会保留并明确报告，可逐条撤销。单次请求 60 秒超时、响应最多 256 KB；迟到响应不会在停止或新会话后修改页面。

本例只授予模型 UI 操作：移动节点、改变布局/可见性/允许的属性、运输方案组件替换、增加 Section 分组。它不能修改业务值或绑定、隐藏主工作台/审批、替换任意组件、生成 CSS/JS/HTML、提交业务或确认执行。宿主权限检查与 SDK 的 schema、revision、硬约束校验一起生效。等待模型时输入发生变化会触发版本冲突，不自动覆盖新状态。

## 哪些变化由运行时负责

页面外壳 `live-application` 与业务表单 `incident-recovery` 都是实际 Surface，使用同一个 Store 和注册组件体系。外壳包含导航、标题、概览、指标、工作台、共享视图与事件面板。

- 对话产生的语义操作调用真实 `AgentUIToolRuntime`，经过 schema 与 revision 校验后写入 Store。
- 主题、导航方向和密度只能从注册组件允许的枚举中选择。对应 CSS 由本地可信 React Pack 提供；Wire 中不接受任意 CSS、DOM 或 JavaScript。
- 每条成功变更保留界面快照。撤销使用当前 `data`，只恢复旧结构；不会覆盖撤销前刚刚编辑的数据。
- 页面外壳的变更不修改业务确认快照。业务表单正在确认或执行时，禁止通过对话重组表单结构。

对话控制区与浏览器式预览边框属于演示宿主，保持固定，让应用变化有稳定的参照。右侧应用内部的页面外壳、表单、确认与结果均由 SDK 渲染。

## 边界

固定模板模式没有 LLM 推理；临时模型模式会实际请求使用者配置的服务。初始页面、主题 CSS 和业务组件仍是可信的预写实现，模型只能组合注册能力，不能凭空生成任意应用。业务数据与外部执行仍是模拟的，状态共享限于同页同一个 Store。撤销最多 40 步、对话最多 80 条，仅存在当前会话内存，不是持久审计或跨设备协作系统。

自动化测试使用明确的协议响应 fixture 验证 SDK 执行、权限拒绝、取消和错误，不把它当成真实大模型推理验收。真实服务还需要用自己的临时配置检查模型质量、额度与 CORS。
