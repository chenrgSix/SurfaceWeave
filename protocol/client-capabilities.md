# Surface Client Capabilities 1.0

Surface Client Capabilities is an optional, JSON-only handshake generated by a
trusted SurfaceWeave host. It describes what the current client can actually
render and which optional Runtime features are available before an Agent asks
for a Surface.

The object is data, not authority. Receiving a capability object from a remote
Agent must never register a Component Pack, install a binding, enable an action,
change an Executor, or widen local resource policy.

## Shape

```json
{
  "wireProtocolVersion": "1.0",
  "rendererKind": "react",
  "terminalCapabilities": ["web"],
  "runtimeCapabilities": ["operations", "tool-invocation"],
  "acceptedPackVersions": { "default": ["1.0.0"] },
  "components": [],
  "packs": [],
  "resourcePolicy": {
    "enabled": true,
    "limits": { "maxNodes": 500, "maxOperationsPerBatch": 50 }
  }
}
```

`components` and `packs` are projections of the host's trusted semantic
registry after applying renderer kind, enabled-Pack allowlist, terminal
capabilities, and accepted versions. They contain no framework binding,
Provider, callback, DOM object, dynamic import, or vendor implementation.

The host may attach this snapshot to its first Agent request using any
transport. SurfaceWeave performs no network request and does not prescribe an
Agent SDK envelope.

The normative Draft 2020-12 Schema is
`schemas/surface-client-capabilities-1.0.schema.json`. It references the
existing Component Pack Manifest definition from Wire Protocol 1.0 but does
not change any Wire Protocol field or event.
